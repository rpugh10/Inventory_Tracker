5.In your DTO you need to add the getters and setters. Use @Data from Lombok

6.Difference between orElse and orElseGet. 
orElse: expects a direct value not a lambda. Java tries to compute the value right away.
orElseGet: Uses a lambda that runs later IF the optional is empty.

7. This line .map(productMapper::toProductDTO)
.map() converts the Product to a toProductDTO
.map(productMapper::toProductDTO) is a cleaner way of writing .map(product -> productMapper.toProductDTO(product)) 
productMapper is the object the holds the tool you want to use. :: Tells Java to look inside that object for the tool. toProductDTO the name of the method you want to run.
Null Safe
The toProductDTO comes from the Mapper Interface

8. Restricting endpoints
Using @PreAuthorize("hasRole('ADMIN')") on a controller method means Only an authenticated user whose Role is ADMIN can execute this method.
To enable @PreAuthorize we need to add @EnableMethodSecurity in the security configuration. 
This tells Spring Security to pay attention to annotations such as @PreAuthorize

9. @Version
This annotation tells hibernate to track row modifications. It prevents two processes from overwriting each others data simultaneously without warning.

11.
FROM eclipse-temurin:24-jre 
This gives our container a Java 24 runtime environment 
The jre means we only need the Java Runtime environment to run our already built JAR we don't need the full JDK
because we are not compiling Java inside this image

12. COPY target/inventoryTracker-0.0.1-SNAPSHOT.jar app.jar
This instruction tells Docker take this JAR from my project and copy it into the Docker image
app.jar is the destination and the stuff before it is the source

13. EXPOSE 8080
Tells Docker what port the application is on at runtime

14. ENTRYPOINT ["java", "-jar", "app.jar"]
Whenever a container is started from this image run this command

15. Docker compose build 
builds or rebuilds Docker images for any services defined in your compose.yaml

15. Docker compose up
 builds, (re)creates, starts, and attaches to containers for all services defined in your compose.yaml

16. Docker compose config
 It essentially compiles and processes your project's configuration without actually building or starting any containers

 17. Docker compose down -v
 stops and entirely removes the containers and networks created by docker compose up
 It essentially cleans up the active deployment infrastructure of your project so it can be rebuilt from scratch next time
 the -v removes postgresql data volume
